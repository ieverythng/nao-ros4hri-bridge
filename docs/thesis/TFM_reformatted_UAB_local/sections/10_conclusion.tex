\chapter{Conclusion}
\label{chap:conclusion}

This thesis presented the design, integration, and validation of a modular LLM-based interactive architecture, implemented with the NAO robot. The contribution combines dialogue routing, compact symbolic grounding, structured planning, a reviewed skill registry, deterministic orchestration, typed execution feedback, simulated and robot-facing skill adapters, and evidence-based user reporting.

The final evidence package contains 108 retained case records from 33 structured runtime traces. Under the primary frozen configuration, 64 of 72 records passed and eight failed the applicable acceptance criteria. The 22-case end-to-end questionnaire produced 20 passes and two failures. The environment profile passed 11/11, the stateful KB chain passed 7/7, the repeated robustness set passed 12/15, and the capability-extreme set passed 5/7.

The architecture demonstrated a complete feedback-driven recovery in the fail-once navigation case. It also rejected two incomplete capability-extreme plans before execution. These results show that generated plans can be constrained by deterministic interfaces and that model errors need not become unrestricted robot actions. They do not show that every failure can be repaired: universal target selection, role preservation, clarification wording, and terminal closure remained variable.

The model comparison further clarifies the meaning of a model-agnostic stack. The planner and execution contracts remained reusable across backends, but semantic quality did not remain constant. Qwen3-VL supplied the complete frozen qualification. Qwen3.5 and the Ollama models had narrower historical evidence, while the final \code{gemma4:31b-cloud} fallback passed only preflight and one dialogue smoke turn. A compatible model must complete the same frozen campaign before it can be treated as an equivalent replacement.

Overall, the thesis supports a bounded conclusion: language-model dialogue and planning can participate in a robot architecture when their outputs are grounded, validated against reviewed skills, dispatched deterministically, and checked against typed feedback and symbolic postconditions. These boundaries do not eliminate non-determinism. They make it observable, limit its authority, and provide a reproducible method for deciding whether a particular model and runtime configuration are safe enough for the tested scope.
