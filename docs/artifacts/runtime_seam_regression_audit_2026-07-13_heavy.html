Remaining Seams

1. Chatbot execution-admission completeness

The adapter preserves or derives selection, but grouped execution can still be handed off without source, recipient, selected members, ordering, or report policy. A selection-required response must retry or clarify before its acknowledgement is spoken.

2. Planner absent-selection policy

Missing selection currently permits broad model and legacy fallback planning. Missing selection for a selection-required operation must be an explicit validation state, not silent permission.

3. Final orchestrator semantic validation

Propagate the normalized selection with plan metadata. Validate exact target coverage, roles, recipient identity, and forbidden extras without moving selection ownership into the orchestrator.

4. Report policy and whole-chain closure

Report policy is inferred from an exact normalized intent label and can disappear even when goal text asks for reporting. Carry the policy structurally and compare report evidence with every selected member.

5. Fake skill effect verification

Journal intended and applied effects by goal and step. Query every selected member after completion. Fake mode does not permit fabricated symbolic success.

6. KnowledgeCore fixture isolation

Use run-unique fixture namespaces and an asserted-effect journal. Remove causal assertions, wait for rematerialization, and prove incoming and outgoing fixture relations are absent.

7. Questionnaire semantic oracle

Add expected target IDs or role selectors, forbidden kinds, sequence shape, report coverage, and KB postconditions. Correlate by goal, plan, version, step, and timestamp.

8. Natural-chat KB mutation schema

Make subject, predicate, and object explicit before planner execution. Keep kb_skills as the mutation transport boundary.

9. Route repair and acknowledgement consistency

Require a valid explicit route and admission payload. On contradiction, retry once or return chatbot-authored clarification. Do not add lexical markers.

10. Compact naming and duplicate identities

Run a paired projection fixture with duplicate semantic names and distinct stable IDs before changing naming code.

Test-First Repair Order

P0-A Selection totality

Require complete structured selection for grouped execution. Missing fields retry or clarify before handoff.

P0-B Final admission

Propagate selection and reject missing, extra, wrong-kind, or wrong-recipient plan steps.

P0-C Report closure

Carry report policy structurally and generate wording from the full selected outcome.

P0-D KB isolation

Use unique namespaces, effect journals, and per-member postcondition queries.

P0-E Semantic scorer

Grade target equality, effects, report coverage, and same-goal lineage.

P0-F Route leakage

Replace contradiction inference with schema retry or safe clarification. Add no markers.

P1 Mutation schema

Require explicit RDF subject, predicate, and object in planner-visible mutation payloads.

P1 Naming probe

Compare duplicate-name projections before accepting any naming refactor.

Prompt gate

No prompt edit is accepted by this audit. Structural contracts explain the strongest failures. Any later wording change requires SkillOpt baseline, bounded mutation, train cases, holdouts, and an accept or reject record.

Clean live acceptance probe

  1. Create a run-unique fixture with one selected table, one unrelated table, three selected objects, and a named recipient.
  2. Visit every selected object with per-target reporting.
  3. Deliver every selected object with a final whole-chain report.
  4. Query every final object location.
  5. Exercise one fail-once member and one blocked member.
  6. Run one dialogue-only future or memory turn, then an explicit execution follow-up.
  7. Score exact IDs, kinds, lineage, effects, and report coverage.

Handoff checklist

  • Preserve person-placement and unchanged-replan guards.
  • Make target selection total where operation semantics require it.
  • Propagate selection to final orchestrator admission.
  • Validate exact visit and delivery member sets.
  • Carry report policy independently of normalized intent loss.
  • Verify every fake skill KB effect.
  • Isolate fixtures and correlate evidence by lineage.
  • Replace route inconsistency inference with retry or clarification.
  • Run SkillOpt before any prompt mutation.

Decision

Bounded handoff

The current dirty runtime set should not be frozen as the final validation baseline. It is safer than the earlier state in person-placement and repeated-block handling, but grouped selection and truthful closure remain optional. Preserve the working hardening and implement the six P0 batches before rescoring.

The score cap may be raised only after the false-success ordered trace and explicit non-action leakage are represented by failing tests and pass from a clean KnowledgeCore state.
