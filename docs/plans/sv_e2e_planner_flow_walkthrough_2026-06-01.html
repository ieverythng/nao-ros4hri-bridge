12) Replanning and Join Policy

Figure 2. Replanning control flow and join policy.
  1. Single active-goal queue model.
  2. goal_id preserves continuity.
  3. plan_id + plan_version encode lineage.
  4. Mid-join uses mapped active step_id when present in new plan.
  5. Fallback front-join starts from first pending step when mapping fails.
  6. Duplicate suppression compares exact tuple goal_id, plan_id, plan_version.

13) Supervisor Demonstration Sequence

  1. Trigger a planner-eligible command and inspect chatbot routing output.
  2. Inspect planner request transport envelope and admitted request payload.
  3. Inspect planner output on /intents and highlight lineage.
  4. Run one success path and one clarification/failure path.
  5. Inspect execution feedback and planner dialogue act payloads.
  6. Close with ownership statement: planner plans, orchestrator dispatches, skills provide live evidence.
