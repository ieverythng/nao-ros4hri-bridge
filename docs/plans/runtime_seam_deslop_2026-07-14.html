Runtime Seam Deslop And Stabilization Plan

Main implementation accepted, deep-fake runtime gate pending, 2026-07-14

Authority: this plan executes the current stabilization tranche under nao_ros4hri_masterplan.md. The masterplan remains the repository-wide integration authority.

Objective

Reduce cross-package churn while preserving grounded execution. Chatbot owns route, target selection, and wording. Planner owns planning and supervision. Orchestrator validates and executes. AB=1 skills provide fresh evidence, and KB transport remains in kb_skills. Deterministic code validates these contracts without replacing valid model output with a second policy.

KB continuitySpatial moves can retain stale relations or accept incomplete post-effect evidence.
Fallback visibilityExisting traces do not consistently state which owner changed semantics.
AttributionContracts, fixtures, fake skills, and harness changes currently share one large work batch.

Retry And Reporting

  • Chatbot receives one validation retry for the failed stage.
  • Planner receives one retry and a conditional second retry only after measurable progress.
  • Repeated output, repeated errors, missing user information, or unavailable backend stop retry.
  • Deterministic salvage occurs only after retry exhaustion and cannot broaden grounded scope.
  • Chatbot remains the report wording authority. Deterministic rendering is an emergency path for empty, unsafe, or factually invalid output.
  • Prompt changes require a complete SkillOpt ledger before acceptance.

Strict KB Effects

  1. AB=1 results provide fresh effect evidence.
  2. Orchestrator validates and delegates through kb_skills.
  3. A move removes stale isIn, isAt, and isOn values before confirming the new relation.
  4. Destination and predicate come from structured evidence, not identifier words.
  5. Missing or contradictory evidence fails the postcondition.
  6. People cannot become supports or deliverable objects.

Validation Ladder

  1. Establish a red test at the narrowest truthful layer.
  2. Patch only the owning seam and run protected controls.
  3. Run package suites, compilation, registry consistency, diff checks, and ROS4HRI audit.
  4. Apply behavior-preserving deslop after green tests, then rerun them.
  5. Build one clean overlay and replace the full stack once.
  6. Run the former failure, a known-good control, focused variants, then full and deep fake suites.

Acceptance

  • Zero healthy-path Tier A fallbacks across dialogue, KB, grounded execution, and report wording.
  • Correct clarification for missing information, with no implicit replan.
  • No false completion, omitted required target, or duplicate speech.
  • Verified KB mutation removes stale relations and preserves human/object roles.
  • Runtime artifacts correlate turn, goal, plan, execution, report, KB, fallback, and latency evidence.
