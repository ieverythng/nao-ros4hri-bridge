Validation Method

PrincipleHow it is applied hereWhy it matters
Scenario modelEach run declares an environment fixture, task prompt, fake policy profile, expected post-condition, and trace artifacts.Scenario-based robot validation literature emphasizes explicit operating context, task, variation conditions, and acceptance criteria so failures are reproducible rather than anecdotal.
Configurable launch surfacepreloaded_environment_ids:=... initializes the sim stack with a stable semantic scene. The questionnaire can override this per run with --preload-environment or per case through environment_ids.ROS 2 launch arguments and parameters are the right seam for repeatable runtime variation. They avoid hidden code edits and make supervisor demos repeatable.
Evidence chainEvery pass must show /kb/revise, /kb/query, grounded context, planner request, fake feedback, execution feedback, and speech outcome when applicable.This separates “fact never existed” from “fact existed but the model ignored it” and from “execution failed but was reported incorrectly.”
Difficulty ladderStart with inventory, then single action, composite action, grouped location delivery, multi-turn pronoun handoff, and finally forced failure/replan.The tests become harder in controlled steps, similar to puzzle-room validation: each scenario isolates one new semantic demand before combining several.
